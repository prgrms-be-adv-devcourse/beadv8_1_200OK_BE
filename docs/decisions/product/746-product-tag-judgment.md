> 이 문서는 #746 작업의 결정과 이유를 남긴 기록이다. 무엇이 바뀌었는지는 PR이 정확하고, 코드가 바뀌었으면 코드가 우선이다.

## 배경

막연한 표현(vague)은 상품명에 글자가 없어 FULLTEXT로 찾을 수 없다. #659가 검색 컬럼 `keywords`와 점수 경로를 만들어 두었지만 값이 비어 있었다. 검색 시점의 LLM 재작성·임베딩은 E3에서 이득이 없어(#659 ADR) 등록 시 보강만 한다. 범위는 판정·저장·백필·태그 0개 상품 조회다. 태그 칩과 필터는 #747, 품목 동의어는 #752다.

## 결정과 이유

|---|---|---|

## 버린 대안

- **OpenAI 자유 키워드, 또는 Jev와 함께:** "함께"는 Jev보다 vague recall +0.061로 더 높지만, product 모듈에 새 외부 연동과 호출 비용이 생기고 칩과 따로 관리해야 한다. OpenAI가 이긴 검색어는 태그 목록에 없는 표현("차례 음식", "매운 양념")이었고, clean 상승분은 품목 동의어(#752)로 얻을 수 있다.
- **판정 결과를 상품 행에 저장:** 상품 version이 올라 판매자 수정과 충돌한다.
- **삭제된 상품용 상태 추가:** 상품 삭제는 되돌릴 수 없어, 상태를 늘리지 않고 판정 행을 지운다.

## 건드릴 때 주의

- `tags.json`은 무엇을 바꾸든 `version`을 올린다. 동의어만 바꿔도 키워드가 바뀌려면 다시 판정해야 하고, 백필은 버전으로 대상을 고른다. 버전을 올리면 다음 기동 때 전체 상품이 다시 판정된다(Jev 호출이 상품 수만큼).
- 선택지 순서는 상품 ID 시드의 자바 `Random`으로 섞는다. 평가 스크립트(파이썬)와 시드는 같지만 순서는 다르다. 평가가 잰 것은 "상품마다 섞인다"는 성질이다.
- 요청 시각은 마이크로초로 자른다. DB 정밀도와 다르면 세대 비교가 늘 달라 결과가 버려진다.
- F8 회귀 테스트는 `keywords`를 비운 채로 잰다. 태그가 운영에서 채워지면 점수 분포가 바뀌므로 점수 하한(#670)을 함께 다시 본다.
- 이 평가셋 수치는 태그 목록 v3를 같은 평가셋 실험 뒤에 다듬은 것이라 다소 낙관적일 수 있다(미확인).
- 최종 실패한 상품은 다음 기동의 백필이 다시 넣는다. 계속 실패하는 상품은 배포 때마다 다시 시도된다.
