## 배경

상품 리뷰의 전체 감성과 여섯 분석 항목 감성을 분류할 모델로, 싸고 빠르다고 알려진 Jev(분류 전용, 한국어 공식 지원 없음)를 써도 되는지 정해야 한다. 기준선은 OpenAI `gpt-5.4-mini`(추론 끔)다. 이번 작업은 분류 기준(명세), 데이터셋과 사람 정답 도구, 두 모델 비교 실행기와 보고서, 본 실험과 채택 결정까지다. 서비스 연동과 구매자 키워드 분석은 범위 밖이다. 도구는 백엔드 코드를 import하지 않아 모듈 밖 `tools/`에 두었지만, 대상이 상품 리뷰라 이 문서는 `product`에 둔다.

## 결정과 이유

| 결정 | 선택 | 이유 |
|---|---|---|
| 리뷰 데이터 | Claude로 1,000개 생성, `synthetic` 표시 | 서비스가 배포 전이고 남의 리뷰는 권한 문제가 있으며, 상업 이용이 확인된 공공 농산물 리뷰를 찾지 못했다. 기준선이 OpenAI라 같은 회사 모델로 만들면 기준선이 자기 계열 문체에 유리해진다 |
| 세트 분리 | 조정용 100 / 평가용 300 / 추가 비교용 600, 시드로 분할 | 조정용으로 명세를 다듬고, 평가용은 그와 섞지 않아야 점수가 부풀지 않는다 |
| 중복 처리 | 정규화한 본문으로 중복 제거, 거의 같은 문장은 분할 뒤 id로 교체(`dataset/replacements.json`) | 같은 문장이 조정용과 평가용에 함께 들어가면 평가가 샌다. 원본 배치를 고치면 중복 제거 결과가 바뀌어 시드가 같아도 분할이 통째로 달라지는 것을 확인했다 |
| 정답 시트 | 본문만 보여 주고 생성 태그는 숨김 | 어려운 사례 유형 같은 태그를 보면 정답자가 의도된 답에 끌려간다 |
| 일치도 | 항목마다 언급 여부 κ와, 둘 다 언급한 칸의 감성 κ를 따로 냄 | 언급 없음까지 한 범주로 섞으면 감성 κ가 0.2여도 전체 κ가 0.784로 나와 기준 0.6을 넘는 것을 계산으로 확인했다 |
| 정답자 | 사람 1명 + 1주 뒤 50개 자기 재채점 (사용자 결정) | 두 번째 정답자가 없다. 모델을 두 번째 정답자로 쓰지 않는다 (버린 대안 참고) |
| 명세 점검 | 조정용 정답을 매긴 뒤 회사가 다른 고급 모델 둘(Claude 계열, OpenAI 계열)에 돌려, 사람 답과 함께 다르게 고른 칸으로 명세를 고침 | 두 모델이 같은 방향으로 다르게 읽은 칸은 명세 문장 쪽 문제일 가능성이 크다. 모델은 정답을 정하는 데 쓰지 않는다. v0.2에서 정한 판정 규칙과 이유는 `tools/review-analysis-bench/criteria/CHANGELOG.md`에 있다 |
| 분류 기준 원본 | `criteria.json` 하나에서 두 제공자 요청을 만듦 | 한쪽에만 예시나 다른 문구가 들어가면 비교가 공정하지 않다 |
| Jev 지시문 | 공통 지시문을 질문마다 앞에 붙임 | Jev API에는 공통 지시문 자리가 없다. OpenAI는 같은 문장을 프롬프트 맨 앞에 한 번 받는다 |
| 선택지 순서 | 리뷰마다 시드로 섞고 두 제공자에 같은 순서를 줌 | Jev는 앞에 나온 선택지를 고르는 경향이 공개돼 있다 |
| 호출 방식 | SDK 없이 `fetch`로 직접 호출 | 재시도 횟수·지연·토큰을 우리 규칙으로 세야 한다. (미확인) OpenAI SDK는 429·5xx를 스스로 재시도해 이 값이 숨는다 |
| 실행기 구조 | 제공자 등록표(요청 만들기·응답 읽기·가격) + 공통 실행기 | 재시도·실패 저장·재실행 규칙이 한 곳에 있어 두 제공자에 똑같이 적용된다 |
| 실행 기록 | 성공·실패 판별 공용체, 실패에는 답 칸 없음 | 실패를 중립이나 언급 없음으로 저장하면 품질 지표가 조용히 틀어진다 |
| 재시도 | 429·5xx·네트워크 오류만 최대 3회 | 다른 4xx는 다시 보내도 같은 답이 온다 |
| 평가용 차단 | 정답 파일이 없거나 빈칸·빠진 리뷰가 있으면 실행기가 요청 전에 멈춤 | 모델 답을 본 뒤 매긴 정답은 정답이 아니다. 문서 규칙만으로는 실수를 못 막아 코드에 넣었다 |
| 항목 감성 Macro F1 | 언급 없음을 평균 낼 범주에 넣지 않음 | 넣으면 언급된 100칸 중 한 칸만 놓쳐도 1.000이 0.796으로 떨어져, 채택 기준(0.70)을 한 칸이 좌우하는 것을 확인했다. 놓친 벌은 언급 여부 지표가 준다 |
| 속도 지표 | 첫 시도에 성공한 요청만으로 중앙값·p95 | 재시도한 요청에는 백오프 대기가 섞여 있다 |
| 평가용 세트 크기 | 300개 대신 무작위 순서인 앞 50개(R0101~R0150)만 본 실험에 씀 (사용자 결정) | 정답을 300개 매기는 시간이 너무 많이 들었다. 팀 프로젝트라 아주 높은 정확도가 필요하지 않아 신뢰도가 떨어지는 것을 받아들였다. 정답을 함께 매긴 다른 15개는 어려워 보이는 것을 골라 무작위가 아니라서 본 실험에 넣지 않았다 |
| 채택 결정 | Jev를 쓴다 (사용자 결정) | 같은 정답 기준에서 두 모델의 품질 차이가 없다고 봤다(전체 감성 Macro F1 차이의 신뢰구간이 0을 포함, 두 모델 답 일치율 92%). 그런데 Jev가 요청당 약 10배 빠르고 1,000건당 약 14배 싸다. 절대 품질 기준(전체 0.75, 항목 0.70)은 두 모델 모두 넘지 못했다. 두 모델이 같은 답을 냈는데 사람 정답과 다른 칸이 몰린 곳이 신선도·상품 상태 경계와 결론 없는 리뷰의 전체 감성이라, 정답과 명세의 어긋남이 큰 원인으로 봤다 |
| PR | 명세·데이터 도구와 비교 실행기를 PR 하나로 (사용자 결정) | PR 하나에 리뷰 대기가 몇 시간에서 하루이틀 걸려, 나누면 대기가 두 번 생긴다 |
| 용어집 | 도구 안에 `GLOSSARY.md`를 둠 | 저장소 루트 용어집은 개인 문서라 커밋되지 않는다 |

## 버린 대안

- **모델을 두 번째 정답자로 쓰기:** Claude 계열은 생성 모델과 같아 생성 의도를 잘 읽고, OpenAI 계열은 기준선과 같아 기준선이 유리해진다. 사람끼리의 일치도라는 κ의 뜻도 바뀐다. 감수하는 것은 정답이 한 사람의 판단이라는 점이고, 자기 재채점으로 일부만 보완한다.
- **원본 배치 파일을 직접 고쳐 중복 교체:** 위 표의 이유로 버렸다.
- **제공자별 실행 스크립트:** 재시도·실패 규칙이 두 벌이 되어 어긋날 수 있다.
- **공식 SDK:** 재시도가 숨고 의존성이 생긴다. 감수하는 것은 요청 형식을 직접 맞춰야 한다는 점이다.
- **Jev를 중계 서비스로 호출:** 중간 서버의 지연이 Jev 속도 측정에 섞인다. 공식 엔드포인트를 쓴다.
- **명세·데이터 도구와 실행기를 PR 둘로 나누기:** 위 표의 이유로 버렸다.

## 건드릴 때 주의

- 평가용 정답을 매기기 시작한 뒤에는 `criteria.json`을 바꾸지 않는다. 바꾸면 이미 매긴 정답과 기준이 어긋난다. 바꿀 때는 `version`을 올리고 `criteria/CHANGELOG.md`, `dataset/labeling-guide.md`의 판정 요약표, 도구 `GLOSSARY.md`를 함께 고친다.
- `dataset/split.ts`를 다시 돌리면 정답 시트의 id가 다른 리뷰를 가리킬 수 있다. 원본 배치를 고치지 말고 `replacements.json`에 교체를 적는다. 교체 항목의 `from`이 지금 본문과 다르면 분할이 멈춘다.
- 조정용 사람 정답은 v0.1 기준이고, 매기는 동안 신선도·상품 상태 경계가 흔들렸다. 조정용 점수로 채택을 판단하지 않는다.
- Jev 모델 목록 API에는 `jev-latest`·`jev-preview`만 보이지만, `jev-1.14.0`으로 요청하면 응답의 `model`도 `jev-1.14.0`이다. `jev-latest`로 바꾸지 않는다.
- OpenAI 요청 형식은 예비 실행에서 응답을 받아 확인했다. 형식은 `src/providers.ts` 한 곳에만 있다.
- 채택 기준 숫자(`src/report.ts`의 `ADOPTION_THRESHOLDS`)는 결과를 보기 전에 고정한 값이다. 이번에는 자기 재채점 없이 그대로 썼고, 모델 결과를 본 뒤에는 바꾸지 않았다.
- 채택 결정은 "Jev가 절대 품질 기준을 통과했다"가 아니라 "같은 조건에서 OpenAI와 품질이 같다"에 근거한다. 근거는 정답자 1명(일치도 미확인)이 매긴 생성 리뷰 50개다. 실제 리뷰가 쌓이면 다시 확인한다.
- 본 실험 결과를 본 뒤 어긋난 리뷰를 확인했으므로, 같은 평가용 50개를 다시 매기면 독립적인 사람 정답이 아니다. 재판정이 필요하면 아직 매기지 않은 평가용 리뷰(R0151 이후, 고른 15개 제외)로 한다.
