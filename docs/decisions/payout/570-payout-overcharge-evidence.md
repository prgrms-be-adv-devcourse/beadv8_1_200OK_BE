## 배경

초과 청구(AMOUNT_MISMATCH) 근거는 #391부터 실패 상세 글(255자) 한 줄에만 있어, 관리자 목록(#569)에서 숫자로 보거나 비교할 수 없었다. 관리자가 "왜 멈췄나(막힌 순간)"와 "지금은 어떤가(지금)"를 나란히 보고 데이터를 고칠지·조정(#291)할지 정하게 하는 것이 범위다. 예전 막힘의 값을 숫자로 쌓아 두는 것, 잘못 해결한 주문이 다시 보이기까지 실행 3번이 걸리는 문제(#590)는 범위 밖이다.

## 결정과 이유

| 결정 | 선택 | 이유 |
|---|---|---|
| 근거 개수 | 실패 상세 글과 같은 8개 (이슈 초안 6개에서 혼자 넘는 주문상품·판매자 수 추가) | "혼자 넘는 주문상품"은 있으면 그 상품이 틀린 게 확실한 가장 강한 근거. 상세 글과 목록이 같은 값을 보여야 관리자가 헷갈리지 않음 (사용자 결정) |
| 막힌 순간 값을 언제 계산하나 | 금액 검사(validate)가 이미 계산하는 값을 그 자리에서 저장 | 근거 합계에는 스냅샷 밖 대기 중(15일 전) 후보가 들어가고(`sumCandidateAmountByOrderInSnapshot`), 대기 중 후보는 Job이 도는 중에도 구매확정으로 늘 수 있음. Job 끝에 다시 계산하면 상세 글과 값이 달라지고, 스냅샷만으로는 검사 때 값을 다시 만들 수 없음 |
| 어디에 저장하나 | 막힌 주문 표에 근거 칸 + 상태 예비(PENDING). 금액 검사가 실패마다 예비 줄로 넣고, Job 끝 갱신이 막힘이면 상태만 바꾸고(근거 유지) 아니면 지움 | 금액 검사 때는 막힘(3번째 실패)인지 모름(횟수는 Job이 성공으로 끝나야 셈). 새 표 없이 "후보는 무시" 규칙으로 감 (사용자 결정, 표 1개 대신 규칙을 안고 감) |
| 이름 | "예비"(PENDING) | "후보"는 정산후보(`PayoutCandidateItem`)와 겹쳐 "후보 합계"와 한 화면에서 섞임 (사용자 결정) |
| 해결된 줄이 이미 있을 때 | 새로 넣지 않고 근거만 바꾸고 상태 그대로 | 주문 ID가 기본 키라 새로 넣으면 중복 오류로 금액 검사가 롤백되어 Job이 매일 실패함. 상태를 두면 "해결됨"이 다음 Job 끝까지 보이는 #582 동작이 그대로 (사용자 결정) |
| 원인에 초과 청구가 없을 때 | Job 끝 갱신이 근거를 비움 | 이슈 완료 조건("초과 청구가 아닌 주문은 비어 있음"). 지금은 거의 안 생기고 조정(#291) 뒤 대비 |
| 지금 값 | 목록 한 페이지의 초과 청구 주문을 묶어 조회 3번으로 계산. 넘친 금액은 0·음수도 그대로 | 주문마다 조회하지 않음(규모 전제). 음수도 "얼마나 여유가 생겼나"라는 근거 |
| 목록 값 저장 | 쉼표로 이은 글을 TEXT 칸에 | 화면에 보여 주기만 하고 DB에서 안을 찾을 일이 없어 표를 따로 두지 않음. 길이를 넘겨 금액 검사가 롤백되면 매일 실패하므로 VARCHAR 대신 TEXT |

## 버린 대안

- **Job 끝에 다시 계산(이슈 초안):** 금액 검사와 Job 끝 사이 구매확정으로 상세 글과 값이 달라질 수 있음. "틀릴 수 있다"고 적어 두면 한 화면에 같은 값이 두 군데 다르게 나와 관리자가 어느 쪽을 믿을지 헷갈림.
- **실패 기록 시각 이전 후보만 세기:** 틈이 금액 검사 안(읽기~저장, 몇 초~몇십 초)으로 줄지만 0이 아님.
- **실패 상세 글을 읽어 8칸으로 나누기:** 255자에서 뒤(이미 지급 목록 이후)가 잘리고, 실패 기록이 쌓기만 하는 표라 글 모양을 영원히 못 바꿈.
- **근거만 담는 새 표:** 정확하고 규칙도 필요 없지만 표가 하나 더 늘어남. 사용자가 표 대신 "예비 줄 거르기" 규칙을 택함.
- **실패 기록 표에 근거 칸:** 실패 기록은 후보마다 한 줄이라 같은 근거가 후보 수만큼 반복되고, 초과 청구가 아닌 줄은 칸이 비어 있음.

## 건드릴 때 주의

- 이 표를 읽는 곳은 모두 PENDING을 걸러야 함: 관리자 목록·개수(`notPendingBlockedOrder`), 해결 API(예비 줄은 해결됨으로 안 바꿈), 앞으로 #392 판매자 화면, #583 범위 비교. 하나라도 빠지면 막히지 않은 주문이 막힘으로 보임.
- 근거 칸은 원본에서 다시 만들 수 없는 값이라 Job 끝 다시 판정·#583 바로잡기가 다시 계산해 덮으면 안 됨. 줄이 잘못 지워졌다 다시 생기면 근거가 빈 채 남고, #583에서 "원인에 초과 청구가 있는데 근거가 빈 줄"로 찾음. 값은 실패 상세 글에 남음.
- 숫자 칸은 "지금 막혀 있는 그 막힘"의 값 하나뿐. 같은 막힘의 1·2번째 실패는 원인 칸 상세 글로, 예전 막힘은 해결 기록 조회(#571)의 상세 글로 봄.
- 실패 상세 글·막힌 순간·지금이 모두 `PayoutAmountValidator.overchargeEvidence` 하나로 만들어짐. 상세 글 모양(`OVERCHARGE_DETAIL`)은 쌓인 예전 기록과 맞춰야 해서 바꾸지 않음.
- 해결된 줄은 해결 뒤 다시 실패하면 그 실패 때 값으로 근거가 바뀐 채 다음 Job 끝까지 보일 수 있음(설계대로, 응답 설명에 적음).
