# 세션 요약 불러오기

`session-summary`가 남긴 요약을 새 세션에 담아 "그 당시 왜 그렇게 했는지"를 알고 시작하게 한다. 요약을 전부 읽지 않고, 후보를 고르는 일은 서브에이전트에게 맡기고, 무엇을 담을지는 사용자가 정한다.

## 인수

PR 번호(`334`, `#334`), PR 제목 일부, 키워드(`delivery`, `정산`)를 받는다. 비어 있으면 현재 브랜치 이름과 최근 커밋 제목에서 키워드를 뽑는다.

## 절차

1. **문서 폴더를 찾는다.** `session-summary`와 같다. 환경변수 `SESSION_DOCS_DIR`, 없으면 레포 루트의 `docs-sessions/`. 둘 다 없거나 비어 있으면 `git submodule update --init docs-sessions`를 안내하고 멈춘다.
2. **최신으로 맞춘다(읽기 전용).** `git -C <폴더> pull --ff-only`. 실패해도 멈추지 않고 "최신이 아닐 수 있다"고만 알린다.
3. **색인을 로컬에서 만든다.** 색인은 문서 레포에 커밋되지 않으므로 읽기 전에 새로 만든다.
   ```bash
   bash .claude/skills/session-summary/build-index.sh <폴더>
   ```
   현재 레포 이름은 `git remote get-url origin | sed -E 's#.*/##; s#\.git$##'`로 구한다.
4. **후보를 고른다 (서브에이전트).** 색인이 10건 이하이면 직접 읽고 골라도 된다(이 경우 서브에이전트를 띄우는 비용이 더 크다). 그보다 많으면 읽기 전용 서브에이전트(`Explore` 또는 `general-purpose`)에게 아래를 맡긴다. 색인이 커져도 메인 컨텍스트를 쓰지 않으려는 것이다.
   - `sessions/index.md`를 읽고 인수와 관련된 항목을 고른다. 기본은 현재 레포의 요약이다. 인수가 프론트엔드·백엔드를 언급하거나 후보의 `related`가 다른 레포를 가리키면 그 레포의 짝 PR도 후보로 올린다. 색인으로 모자라면 해당 후보 파일의 머리말과 `## 목적`만 읽는다. 본문 전체를 읽지 않는다.
   - 후보마다 `related`로 이어진 이전·이후 PR도 함께 후보로 올린다.
   - 결과를 표로 돌려준다: `레포 | PR | 제목 | 고른 이유 한 줄 | 가치(상/중/하) | 예상 줄 수 | 낡았을 가능성`.
   - 낡았을 가능성은 문서의 `head` 이후 해당 영역이 바뀌었는지로 판단한다. 문서에 적힌 파일이나 클래스가 지금 코드에 있는지 `git log`나 `grep`으로 확인한다. 확인하지 못했으면 "확인 못 함"이라고 적는다.
   - 서브에이전트는 파일을 수정하지 않고, 판단 근거를 추측으로 채우지 않는다.
5. **사용자에게 고르게 한다.** 후보 표를 보여주고 무엇을 담을지 묻는다(여러 개 선택 가능). 추천을 첫 번째로 둔다. 고르기 전에는 본문을 컨텍스트에 불러오지 않는다.
   - 질문 도구(`AskUserQuestion`)를 쓸 수 없는 환경(예: `claude -p` 헤드리스)이면 묻지 않고, 후보 표의 추천 상위 항목(가치 "상", 최대 3개, 합계 약 600줄)을 그대로 불러온다. 그때는 "질문할 수 없어 추천 항목을 자동으로 골랐다"고 한 줄로 알리고 고른 PR 번호를 적는다.
6. **고른 문서만 읽는다.** 한 번에 최대 3개, 합계 약 600줄까지만 담는다. 더 많이 고르면 줄이도록 안내한다.
7. **요약해서 알린다.** 읽은 뒤 전체 15줄 이내로 정리한다. 문서를 되풀이하지 말고 지금 작업에 필요한 것만 고른다.
   - 지금 작업에 영향을 주는 결정과 그 이유
   - 이미 버린 방법(다시 시도하지 않도록)
   - 알려진 약점과 남은 과제
   - `(미확인)`으로 표시된 주장 목록

## 주의

- **요약은 당시 기준이다.** 코드가 우선이다. 요약의 주장이 지금 코드와 다르면 코드를 따르고, 다르다는 사실을 사용자에게 알린다.
- **옛 결정이 지금 판단을 붙잡지 않게 한다.** 요약의 결정은 "그때의 이유"이지 "지금도 맞는 규칙"이 아니다. 이유가 지금도 유효한지 먼저 확인한다.
- 문서 레포를 수정하지 않는다. 틀린 내용을 발견하면 사용자에게 알리고, 정정은 `session-summary`의 후속 절로 한다.
