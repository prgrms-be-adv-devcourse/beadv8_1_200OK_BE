# 세션 요약 작성

PR 하나를 만든 세션에서 "무엇을 왜 그렇게 정했는지"를 문서 레포에 남긴다. 다음에 같은 기능을 고칠 때 `session-context` 스킬로 불러와 AI에게 그 당시 맥락을 준다.

## 먼저 알아둘 것

- **결정의 이유는 대화에만 있다.** 코드와 diff에는 없다. `/clear`나 `/compact`를 한 뒤에는 이유가 사라지므로, 결정이 오간 같은 세션에서 PR을 올린 직후에 실행한다. 세션이 이미 비워졌다면 git 기록으로 알 수 있는 것만 쓰고 그 사실을 문서에 적는다.
- 문서 레포는 프로젝트 코드와 별개이고, 같은 서비스의 백엔드·프론트엔드 레포가 함께 쓴다. PR 번호는 레포 안에서만 유일하므로 요약 문서는 **레포와 PR 번호로 구분**한다. 파일은 `sessions/<레포>/<PR번호>-<slug>.md`다.
- 레포 이름은 `git remote get-url origin`의 마지막 경로에서 `.git`을 뺀 것이다(예: `beadv8_1_200OK_BE`).
  ```bash
  git remote get-url origin | sed -E 's#.*/##; s#\.git$##'
  ```

## 절차

1. **PR을 정한다.** 인수로 PR 번호를 받으면 그것을 쓴다. 없으면 현재 브랜치의 PR을 찾는다.
   ```bash
   env -u GITHUB_TOKEN gh pr view --json number,title,headRefName,baseRefName,url
   ```
   PR이 없으면 만들지 말고 "PR을 먼저 올린다"고 알리고 멈춘다.
2. **문서 폴더를 찾는다.** 순서대로 확인해 처음 맞는 곳을 쓴다.
   1. 환경변수 `SESSION_DOCS_DIR`
   2. 현재 레포 루트의 `docs-sessions/` (서브모듈)

   둘 다 없거나 비어 있으면(`git -C <폴더> rev-parse --is-inside-work-tree`가 실패) 아래처럼 알리고 멈춘다. 추측해서 다른 곳에 만들지 않는다.
   ```bash
   git submodule update --init docs-sessions
   ```
   worktree에서 실행할 때는 서브모듈이 비어 있을 수 있으니 `SESSION_DOCS_DIR`을 쓰라고 안내한다.
3. **최신 상태로 맞춘다.** `git -C <폴더> pull --ff-only`. 실패하거나 푸시하지 않은 변경이 있으면 사용자에게 알리고 멈춘다. 문서 레포의 `.gitignore`에 `sessions/index.md`가 없으면 사용자에게 알린다(색인은 커밋하지 않는다).
4. **같은 PR의 요약이 있는지 본다.** `<폴더>/sessions/<레포>/<PR번호>-*.md`가 있으면 덮어쓰지 않는다. 사용자에게 묻고, 이어 쓰기를 고르면 그 파일 끝에 `## 후속 (YYYY-MM-DD)` 절만 덧붙인다. 기존 내용은 고치지 않는다.
5. **근거를 모은다.**
   ```bash
   git log <base>..HEAD --format='%h %s'
   git diff --stat <base>...HEAD
   ```
   `base`는 PR의 기준 브랜치(`origin/<baseRefName>`)다. "왜"는 이 대화에서 가져온다. 사용자가 정한 결정, 검토한 대안, 시도했다가 버린 것, 부딪힌 문제와 해결, 확인한 것과 못 한 것이다.
6. **템플릿으로 쓴다.** 이 스킬 폴더의 `template.md`를 따른다.
   - 머리말의 `title`은 PR 제목에서 `<Type>: ` 접두를 뺀다. `summary`는 무엇을 왜 했는지 한 줄이다. `head`는 `git rev-parse --short HEAD`다.
   - API 계약이나 화면·응답 형식을 바꾸는 작업이면, 짝이 되는 다른 레포(프론트엔드·백엔드)의 PR이 있는지 사용자에게 묻고 있으면 `related`에 `<레포>#<PR번호>`로 적는다. 모르면 빈 목록으로 둔다.
   - 코드나 테스트로 확인하지 않은 주장은 문장 앞에 `(미확인)`을 붙인다. 이 대화에서 읽거나 돌려 본 것만 "확인했다"고 쓴다.
   - 코드나 PR 본문에 이미 있는 내용은 되풀이하지 말고 "왜"만 적는다. 전체 200줄 안쪽으로 쓴다.
   - 템플릿의 작성 규칙 주석은 지운다.
7. **민감 정보를 점검한다.** 토큰, 비밀번호, API 키, IP 주소, 이메일, 내부 URL이 있는지 본다. 있으면 지우고 저장한다.
   ```bash
   grep -nEi '(password|secret|token|api[_-]?key)[[:space:]]*[:=]|[0-9]{1,3}(\.[0-9]{1,3}){3}|[A-Za-z0-9._%+-]+@[A-Za-z0-9.-]+\.[a-z]{2,}' <파일>
   ```
8. **저장한다.** `<폴더>/sessions/<레포>/<PR번호>-<slug>.md`에 쓴다(`<레포>` 폴더가 없으면 만든다). `slug`는 영문 소문자·숫자·하이픈 2~4단어다(예: `delivery-hexagonal`). 한글 제목이면 핵심 영문 용어로 직접 짓는다.
   - 색인(`sessions/index.md`)은 만들지도 커밋하지도 않는다. 여러 사람이 `main`에 직접 올리면 생성 파일이 매번 충돌하기 때문이다. 색인은 읽는 쪽(`session-context`)이 로컬에서 만든다.
9. **사용자에게 확인받는다.** 저장한 파일과 `git -C <폴더> status --short`, 요약의 `(미확인)` 항목 목록을 보여주고 문서 레포에 커밋·푸시해도 되는지 **명시적 승인**을 받는다. 승인 전에는 커밋하지 않는다.
10. **승인 후 커밋하고 푸시한다.** 문서 레포는 `main`에 직접 올린다.
    ```bash
    git -C <폴더> add sessions/<레포>/<PR번호>-<slug>.md
    git -C <폴더> commit -m "Docs: <레포> PR #<PR번호> 세션 요약 추가"
    git -C <폴더> pull --rebase origin main
    git -C <폴더> push origin main
    ```
    - 파일을 이름으로 지정해 `git add`한다(`git add -A` 금지). 커밋 메시지는 한글이고 AI 표기를 넣지 않는다.
    - 푸시가 거절되면(`non-fast-forward`) `pull --rebase` 후 한 번만 다시 시도한다. 그래도 실패하면 알리고 멈춘다. `--force`는 쓰지 않는다.
11. **마무리한다.**
    - 서브모듈이면 프로젝트 쪽 포인터는 올리지 않는다(`ignore = all`).
    - PR 본문에 넣을 링크 한 줄을 알려준다. PR 본문은 사용자가 요청하기 전에는 고치지 않는다.

## 쓰지 않는 것

- 작성자, 머지 여부, 머지 커밋, 기능 태그, 파일 목록은 머리말에 넣지 않는다. 리팩터링으로 바뀌거나 작성 시점에 알 수 없다.
- 이미 저장한 요약을 고치지 않는다. 틀린 내용은 `## 후속`으로 정정한다.
