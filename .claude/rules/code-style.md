# 코드 포맷

import, 빈 줄, 주석, TODO, Javadoc을 작성할 때 따르는 규칙이다.
사람용 원문: `docs/CONVENTION.md` 10절.

## import·파일 끝·빈 줄

- 와일드카드 import(`*`)를 쓰지 않고 클래스를 하나씩 import한다.
- 파일은 마지막 줄 뒤에 개행 한 줄로 끝낸다. 개행이 없거나 빈 줄이 여러 개 이어지지 않게 한다.
- 빈 줄을 연속해서 두지 않는다(한 줄까지). `{` 바로 다음이나 `}` 바로 앞의 빈 줄은 허용한다.

**이유**: `*` import는 어떤 클래스를 쓰는지 한눈에 보이지 않고 같은 이름의 클래스가 여러 패키지에 있으면 충돌한다. 파일 끝 개행이 없으면 diff에 "No newline at end of file"이 표시된다. 구분용 빈 줄은 읽기 쉽게 하므로 과한 여백만 막는다.

```java
// O
import jakarta.persistence.Column;
import jakarta.persistence.Entity;

// X
import jakarta.persistence.*;
```

## 주석

- 주석은 한국어로 쓴다.
- 코드를 보면 알 수 있는 **무엇**이 아니라, 코드만으로 알기 어려운 **왜**(이유, 제약, 결정)를 쓴다.
- 클래스와 공개 메서드 설명은 Javadoc(`/** */`), 메서드 안의 설명은 `//`로 쓴다.

**이유**: "왜"를 쓴 주석은 코드가 바뀌어도 낡지 않고, 코드를 그대로 옮긴 주석은 코드가 바뀔 때 어긋나기 쉽다.

```java
// O
// 판매자는 뽑혔는데 후보가 0건 = 두 조회 조건 불일치(버그). 그대로 두면 같은 판매자가 계속 뽑혀 무한 반복되므로 실패시킴
if (candidates.isEmpty()) { ... }

// X: 코드를 그대로 옮긴 주석
// 회원 저장
Member saved = save(member);
```

## TODO

- 형식은 `// TODO(#이슈번호): 할 일과 이유`이다.
- 할 일과 함께 이유나 현재 상태를 적는다.
- 이슈 번호가 없으면 이슈를 만든 뒤 번호를 적는다. 팀 논의가 필요해 이슈로 만들기 어려우면 `TODO(논의 필요)`로 쓰고 무엇을 논의해야 하는지 적는다.
- TODO를 해결하면 같은 PR에서 주석을 지운다.

**이유**: 이슈 번호가 있어야 TODO를 추적할 수 있고, 할 일만 적으면 왜 남겼는지 알 수 없다. 해결한 TODO를 남겨 두면 코드와 어긋난 주석이 된다.

```java
// O
// TODO(#52): 실행 기록은 현재 메모리 저장 (batch-jdbc 미적용), DB 저장 여부 논의 필요
// TODO(논의 필요): 원 미만 처리 방식(버림/반올림/올림) 팀 확정 필요. 현재는 버림 기준.

// X
// TODO: API 작업 시 응답 DTO 위치·형식 정리
```

## Javadoc

1. 첫 문장은 무엇을 하는지 한 문장으로 요약하고 "~한다"로 끝낸다. 클래스는 맡은 책임을 한 문장으로 쓴다.
2. 첫 문장으로 부족한 내용(이유, 제약, 이벤트 발행 같은 부수 효과)은 빈 줄 없이 다음 줄에 이어서 쓴다.
3. 태그는 필요한 것만 쓴다.
   - `@param`: 이름만으로 의미·단위·제약을 알기 어려운 매개변수만 쓴다.
   - `@return`: 반환값의 의미가 이름만으로 분명하지 않을 때 쓴다.
   - `@throws`: 호출하는 쪽이 알아야 하는 예외를 쓴다. `RestApiException`은 던지는 에러 코드 이름을 적는다.
4. getter, 이름만으로 충분한 메서드, `@Override`한 메서드, private 메서드에는 쓰지 않아도 된다.
5. 코드나 이름은 `{@code ...}`, 다른 클래스는 `{@link ...}`로 쓴다.

**이유**: 이름을 되풀이할 뿐인 태그를 모두 채우면 도움이 되지 않고 코드가 바뀔 때 어긋난다. 필요한 정보만 쓰면 작성 부담도 줄고 읽기 쉽다.

```java
// O
/**
 * 일반 회원(구매자)을 생성한다.
 * 이용약관·개인정보 수집·이용 동의는 요청 검증 단계에서 확인된 상태여야 하며, 두 동의 일시는 agreedAt으로 기록한다.
 *
 * @param encodedPassword 인코딩된 비밀번호 (평문 금지)
 * @param agreedAt        약관 동의 일시
 */

/**
 * 회원가입을 처리한다.
 *
 * @throws RestApiException 아이디나 이메일이 중복이면 {@code DUPLICATE_LOGIN_ID}, {@code DUPLICATE_EMAIL}
 */

// X: 이름을 되풀이하는 태그를 모두 채운다
/**
 * 회원을 생성한다.
 *
 * @param loginId 로그인 아이디
 * @param email 이메일
 */
```
