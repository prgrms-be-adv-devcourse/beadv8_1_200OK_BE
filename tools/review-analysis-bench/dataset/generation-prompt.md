# 생성 리뷰 지시문

공공 데이터에서 상업 이용이 확인된 농산물·식품 리뷰를 찾지 못해(2026-11-03), 리뷰 1,000개를 생성한다. 기준선이 OpenAI(`gpt-5.4-mini-2026-03-17`)라서 생성 모델은 Claude(`claude-opus-5-5`)를 쓴다. 같은 회사 모델로 만들면 기준선이 자기 계열 문체에 유리해지기 때문이다.

생성 리뷰에는 모두 `synthetic: true`를 붙이고, 보고서에 "생성 데이터 기준 결과"라고 밝힌다.

## 배치 구성

| 배치 | 개수 | 내용 | 쓰이는 세트 |
|---|---|---|---|
| hard-tuning | 100 | 아래 어려운 사례 유형을 고루 | 기준 조정용 100 |
| hard-eval | 60 | 같은 유형, 다른 문장 | 평가용 300 중 어려운 사례 |
| general-1 | 210 | 과일 | 평가용 240 + 추가 비교용 600에 무작위로 나눔 |
| general-2 | 210 | 채소·곡물 | 〃 |
| general-3 | 210 | 가공품(떡, 즙, 잼, 김치, 꿀, 말린 과일 등) | 〃 |
| general-4 | 210 | 버섯·견과·나물·제철 과일 섞음 | 〃 |

| general-5 | 12 | 보충분(섞음) | 〃 |

`split.ts`는 띄어쓰기·문장부호만 다른 리뷰를 하나만 남긴다. 2026-11-03 첫 생성에서 "좋아요", "그냥 그래요" 같은 짧은 상투어 10개가 배치끼리 겹쳐 빠졌다. 그래서 general-5(12개)를 보충하고, hard-eval에서 빠진 E06(한마디 리뷰) 1개를 더 썼다(hard-eval 61줄). 같은 문장이 조정용과 평가용에 함께 들어가면 평가가 새므로 중복은 남기지 않는다.

정규화로 걸러지지 않는 거의 같은 문장(한 글자 차이, 같은 문장 틀)은 분할 뒤 바이그램 유사도로 찾아 [`replacements.json`](replacements.json)에서 평가용 쪽 본문을 새로 썼다. 교체한 본문도 같은 생성 모델(`claude-opus-5-5`)이 썼고 유형 태그는 유지했다.

일반 배치는 생성할 때 어느 세트로 갈지 모른다. 세트는 `dataset/split.ts`가 시드로 나눈다.

## 공통 규칙

- 한국 온라인 쇼핑몰의 실제 구매 후기처럼 쓴다. 너무 정돈된 문장은 피한다.
- 별점, 상품명 머리말, 번호를 본문에 넣지 않는다.
- 분석 항목(맛·신선도·상품 상태·포장·배송·가격) 가운데 0~4개를 자연스럽게 언급한다. 여섯 개를 다 나열하는 리뷰는 만들지 않는다.
- 같은 문장 틀을 반복하지 않는다. 배치 안에서 첫 어절이 같은 리뷰가 5%를 넘지 않게 한다.
- 정답 라벨은 쓰지 않는다. 사람이 모델 결과와 생성 의도를 보지 않고 정답을 매겨야 하기 때문이다.

## 일반 배치 비율 (겹칠 수 있음)

| 특징 | 비율 | 태그 |
|---|---|---|
| 오타·띄어쓰기 틀림 | 15% | `typo` |
| 초성체·ㅋㅋ·이모티콘 | 10% | `slang` |
| 한 줄 리뷰(20자 이하) | 25% | `short` |
| 긴 리뷰(150자 이상) | 15% | `long` |
| 반어 | 5% | `irony` |
| 부정문("안 달아요", "나쁘지 않아요") | 15% | `negation` |

리뷰 전체의 의도한 분위기 비율은 대략 긍정 45%, 부정 30%, 혼합 15%, 중립 10%다. 부정 재현율을 재려면 부정 리뷰가 충분해야 해서 실제 쇼핑몰보다 부정을 많이 둔다.

## 어려운 사례 유형

| 코드 | 유형 | 예 |
|---|---|---|
| B01 | 무름·곰팡이 | "물러졌어요", "곰팡이 폈어요" |
| B02 | 멍·찍힘·크기·사진과 다름 | "크기가 사진보다 작아요" |
| B03 | 당도·식감 | "당도가 낮아요", "퍽퍽해요" |
| B04 | 양이 적음 (가격 언급 있는 것과 없는 것 반반) | "양이 적어요", "가격 대비 양이 적네요" |
| B05 | 박스 찌그러짐 | "박스가 찌그러져 왔어요" |
| B06 | 포장 탓에 생긴 손상 | "포장이 부실해서 멍들었어요" |
| B07 | 원인 없는 손상 | "멍들었어요" |
| B08 | 늦은 배송 탓에 상함 | "늦게 와서 다 상했어요" |
| B09 | 판매자 응대만 언급 | "사장님이 친절하세요" |
| B10 | 가공품 유통기한 | "유통기한이 이틀 남았어요" |
| E01 | 결론 없이 항목끼리 갈림 | "맛은 최고인데 배송이 너무 늦었어요" |
| E02 | 평가 없는 언급 | "맛은 그냥 그래요" |
| E03 | 반어 | "배송 참 빠르네요^^ 일주일 걸림" |
| E04 | 불만이 있지만 결론이 있음 | "배송은 늦었지만 맛있어서 재구매해요" |
| E05 | 부정문 | "나쁘지 않아요", "생각보다 안 달아요" |
| E06 | 한마디 | "좋아요", "별로" |

어려운 사례 배치는 유형마다 개수를 고르게 하고, 한 리뷰에 유형을 하나만 의도한다. 유형 문장 앞뒤에 평범한 문장을 붙여 실제 리뷰처럼 만든다.

## 출력 형식

한 줄에 리뷰 하나인 JSONL로 쓴다.

```json
{"product":"부사 사과 5kg","productType":"fresh","text":"...","tags":["short","typo"],"hardCase":null}
```

- `productType`: `fresh`(신선 식품) 또는 `processed`(가공품)
- `tags`: 위 태그 가운데 해당하는 것. 없으면 `[]`
- `hardCase`: 어려운 사례 배치에서만 유형 코드. 일반 배치는 `null`
