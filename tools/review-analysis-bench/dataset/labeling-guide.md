# 사람 정답 매기기 지침

분류 기준은 [`criteria/criteria.json`](../criteria/criteria.json)이다. 모델에 주는 질문과 같은 문서를 보고 매긴다. 이 지침에는 입력 방법과 절차만 쓴다.

## 지켜야 할 것

- **모델 결과를 보기 전에 매긴다.** 평가용 300개는 정답을 다 매긴 뒤에 모델에 돌린다.
- 두 명이 매기면 서로의 시트를 보지 않는다. 다른 칸만 나중에 논의한다.
- 생성 데이터의 태그(`data/reviews.jsonl`의 `tags`, `hardCase`)를 보지 않는다. 의도된 답에 끌려간다.
- 별점은 없다. 본문만 보고 판단한다.

## 입력 코드

| 코드 | 뜻 | 쓰는 칸 |
|---|---|---|
| `p` | 긍정 | 전체, 항목 |
| `n` | 부정 | 전체, 항목 |
| `o` | 중립 | 전체, 항목 |
| `m` | 혼합 | 전체, 항목 |
| `-` | 언급 없음 | 항목만 |
| `?` | 판단 불가 | 전체, 항목 |

- 판단 불가는 언급은 있는데 감성을 정할 수 없을 때만 쓴다. 언급이 없으면 `-`다. 모델 선택지에는 없고, 품질 지표에서 빼고 개수만 보고한다.
- 헷갈린 칸은 `note`에 이유를 짧게 적는다. 명세를 다듬을 때 이 메모를 본다.
- 스프레드시트에서 `-`가 수식으로 바뀌면 `'-`로 입력한다.

## 순서

1. `node dataset/make-sheets.ts <이름>`으로 시트를 만든다(`data/labels/<이름>/tuning.csv`, `eval.csv`).
2. **조정용 100개**를 먼저 매긴다. 헷갈린 사례로 `criteria.json` 문구와 경계 판정 표를 고치고 버전을 올린다.
3. 명세를 고친 뒤 **평가용 300개**를 매긴다. 평가용을 매기기 시작한 뒤에는 명세를 고치지 않는다. 고치면 이미 매긴 정답과 기준이 어긋난다.
4. `node dataset/check-sheet.ts data/labels/<이름>/eval.csv`로 빈칸과 잘못된 코드를 찾는다.
5. 일치도를 낸다.
   - 두 명: `node dataset/agreement.ts data/labels/<A>/eval.csv data/labels/<B>/eval.csv eval`
   - 혼자: 1주 뒤 `node dataset/make-sheets.ts <이름>-recheck`로 50개 시트를 만들어 다시 매기고(이전 시트를 보지 않는다) `node dataset/agreement.ts data/labels/<이름>/eval.csv data/labels/<이름>-recheck/eval.csv eval-self`
6. 정답 파일을 만든다.
   - 두 명: `-disagreements.csv`의 다른 칸을 논의해 `-gold-draft.csv`의 `a|b` 칸을 고친다. `check-sheet.ts`를 통과하면 `data/labels/gold-eval.csv`로 저장한다. agreement를 다시 돌려도 고친 초안은 덮어쓰지 않는다(`--force`를 줄 때만 덮어쓴다).
   - 혼자: 처음 매긴 `data/labels/<이름>/eval.csv` 300행 전체가 정답이다. 다시 매긴 50개는 κ를 내는 데만 쓴다. 그대로 `data/labels/gold-eval.csv`로 복사한다.
7. κ는 항목마다 둘로 나온다. 언급 여부 κ(언급 없음 대 나머지)와, 두 사람이 모두 언급한 칸의 감성 κ다. 둘 중 하나라도 0.6 미만이면 그 항목의 명세를 먼저 고치고 다시 매긴다. 언급 없음까지 한꺼번에 섞어 κ를 내면 감성 판단이 엇갈려도 높게 나와서 나눠 본다. 감성 κ 옆의 n이 작으면(예: 20 미만) 몇 칸에 크게 흔들리므로 숫자와 함께 n을 보고한다.
8. κ를 보고 채택 기준 숫자를 한 번만 조정해 고정한다. 모델 결과를 보기 전에 한다.

## 다시 매길 50개

`-recheck` 시트에는 반복 실행용으로 미리 고른 평가용 50개(`repeatRun: true`)가 들어간다. 세트를 나눌 때 시드로 골랐다.
