# 용어

리뷰 분석 실험 도구와 `product` 모듈의 리뷰 분석 서비스에서 함께 쓰는 용어와 피할 말이다. 코드 이름, 문서, 대화에서 같은 말을 쓴다.

판정 규칙(어느 표현을 어느 항목·감성으로 매기는지)의 원본은 [`product/src/main/resources/review-analysis/criteria.json`](../../product/src/main/resources/review-analysis/criteria.json)이다. 이 문서와 어긋나면 `criteria.json`이 기준이고, 기준을 바꿀 때는 `criteria.json`, 이 문서, 보관 브랜치 `feature/385`의 `dataset/labeling-guide.md` 판정 요약표를 함께 고친다.

## 리뷰 분석

**상품 리뷰 (ProductReview)**:
구매자가 리뷰 가능 구매 건 하나에 대해 남기는 별점·내용·첨부. 같은 주문에서 같은 상품을 옵션만 달리 샀어도 리뷰는 하나다. 분석은 본문만 보고, 별점은 정답으로 쓰지 않는다.
_Avoid_: 후기, 평가, 댓글

**분석 항목 (Aspect)**:
상품 리뷰에서 따로 감성을 읽어 내는 정해진 관점. 맛·신선도·상품 상태·포장·배송·가격 여섯 개이며, 판매자 응대나 손편지·서비스 동봉처럼 여기 없는 관점은 전체 감성에만 반영한다. 맛은 당도·식감·향, 신선도는 신선함·변질(무름·곰팡이·시듦, 가공품은 유통기한 포함), 상품 상태는 크기·양·외관·물리적 손상(멍·찍힘·터짐), 포장은 포장재·완충·밀봉 상태, 배송은 속도·일정·배송 기사 응대다. 변질은 신선도에만, 물리적 손상은 상품 상태에만 매긴다. 판매자에게 필요한 조치가 다르기 때문이다(보관·출고 속도와 선별·완충).
_Avoid_: 카테고리(상품 분류와 겹친다), 평가 항목, 속성

**감성 (Sentiment)**:
리뷰가 어떤 대상을 어떻게 평가하는지를 나타내는 값. 긍정·부정·중립·혼합 가운데 하나이고, 분석 항목에는 언급 없음이 더해진다. 점수가 아니라 범주다.
_Avoid_: 점수, 평점, 판정

**전체 감성 (Overall sentiment)**:
리뷰 전체가 상품을 어떻게 평가하는지. 항목 감성을 세어 정하지 않고 따로 판단한다. 리뷰에 재구매·추천·비추천 같은 결론이 있으면 그 결론을 따른다. 결론이 없으면 맛·신선도·상품 상태 같은 상품 자체 평가를 배송·포장·응대보다 무겁게 본다. "맛은 최고인데 배송이 늦었다"는 전체 긍정이다.
_Avoid_: 종합 점수, 대표 감성

**항목 감성 (Aspect sentiment)**:
분석 항목 하나에 대한 감성. 같은 리뷰라도 항목마다 다를 수 있다. "맛은 최고인데 배송이 늦었다"는 맛 긍정, 배송 부정이다.

**긍정 (Positive)**:
만족·칭찬·추천을 표현한 감성. "나쁘지 않아요"처럼 만족 쪽으로 기운 약한 칭찬도 긍정이다.

**부정 (Negative)**:
불만·문제·비추천을 표현한 감성. 반어로 불만을 표현한 것도 부정이다.

**중립 (Neutral)**:
대상을 언급했지만 좋다·나쁘다는 평가가 없는 감성. "그냥 그래요", "무난해요", "배송은 3일 걸렸어요"처럼 사실만 적은 말, "아직 안 먹어봐서 모르겠어요"처럼 평가를 미룬 말이 여기 든다.
_Avoid_: 보통

**혼합 (Mixed)**:
같은 대상에 긍정과 부정 평가가 함께 있는 감성. 결론이 있으면 혼합이 아니라 결론을 따른다("비싸지만 아깝지 않아요"는 가격 긍정). 전체 감성에서는 결론 없이 상품 자체에 둘이 비슷한 무게로 있을 때만 혼합이다.

**언급 없음 (Not mentioned)**:
리뷰에 그 분석 항목을 판단할 근거가 없는 상태. 원인을 짐작해 채우지 않는다. "멍들었다"만 있으면 포장은 언급 없음이다.
_Avoid_: 중립, 해당 없음

**판단 불가 (Undecidable)**:
사람이 정답을 매길 때 언급은 있지만 감성을 정할 수 없는 칸에 붙이는 표시. 모델이 고르는 감성이 아니며, 품질 평가에서 빼고 개수만 따로 센다.
_Avoid_: 중립, 언급 없음

**내용 없는 리뷰 (Empty review)**:
판단 근거가 되는 말이 하나도 없는 상품 리뷰. 빈 내용, 기호·자음만 있는 내용, 의미 없는 반복, 사진만 있는 리뷰다. 분석하지 않는다. "좋아요" 한마디는 내용 없는 리뷰가 아니다.

## 서비스 연동

**재분석 (Re-analysis)**:
수정된 상품 리뷰를 다시 분석하는 일. 본문뿐 아니라 별점만 고친 간단한 수정도 변경으로 보고 다시 분석한다. 내용 없는 리뷰가 수정으로 본문을 얻으면 그때 처음 분석한다.

**분석 요청 (Analysis request)**:
상품 리뷰 하나를 분석 종류(감성, 키워드) 하나로 분석해 달라는 기다리는 일. 리뷰와 분석 종류마다 하나만 있고, 리뷰가 다시 수정되면 같은 요청이 처음부터 다시 시작된다. 분석 종류마다 따로 성공하고 실패한다.

**최종 실패 (Final failure)**:
다시 시도해도 결과를 얻을 수 없다고 보고 분석 요청을 끝낸 상태. 해당 리뷰는 감성 집계에 들지 않는다. 리뷰가 다시 수정되면 새로 분석한다.
_Avoid_: 에러, 분석 불가

**분석 완료 리뷰 (Analyzed review)**:
삭제되지 않았고, 마지막 수정 이후의 분석 결과가 있는 상품 리뷰. 분석 종류마다 따로 정한다. 감성은 분석 완료이고 키워드는 아직인 리뷰가 있을 수 있고, 감성 집계와 키워드 집계는 각자 자기 종류의 분석 완료 리뷰만 센다. 수정된 리뷰는 재분석이 끝날 때까지 분석 완료 리뷰가 아니며, 수정 전 결과로 대신하지 않는다.

**감성 집계 (Sentiment summary)**:
한 상품의 분석 완료 리뷰를 전체 감성과 항목 감성별로 센 것. 판매자에게만 보인다. 구매자에게는 감성 집계 대신 리뷰 키워드를 보인다.
_Avoid_: 감성 통계, 리뷰 분석 결과

**항목 분모 (Aspect denominator)**:
한 분석 항목에서 언급 없음이 아닌 분석 완료 리뷰 수. "맛을 언급한 리뷰 120개 중 긍정 90개"의 120이다. 전체 감성의 분모는 분석 완료 리뷰 수다. 분석을 기다리는 리뷰, 분석에 실패한 리뷰, 내용 없는 리뷰, 삭제된 리뷰는 분모와 분자 어디에도 들지 않는다.

## 리뷰 키워드

**리뷰 키워드 (Review keyword)**:
여러 구매자가 반복해 칭찬한 상품의 장점을 짧은 긍정 표현("달아요", "아삭해요")으로 나타낸 것. 구매자 상품 상세에 칩으로 보인다. 리뷰에서 자유롭게 뽑지 않고 키워드 목록에 있는 것만 쓴다. 부정 표현은 없다.
_Avoid_: 태그, 해시태그, 요약 문구

**키워드 목록 (Keyword list)**:
리뷰 키워드로 쓸 수 있는 표현과 각각의 판정 기준을 모은 목록. 키워드마다 그 키워드를 묻는 상품 분류가 정해져 있어, 상품 분류에 따라 묻는 키워드가 다르다("아삭해요"는 쌀에 묻지 않는다). 화면에 나가는 문구는 늘 이 목록의 현재 문구다.

**목록 버전 (Keyword list version)**:
키워드 목록의 버전. 키워드나 판정 기준, 질문 문구를 바꾸면 올린다. 목록 버전이 바뀌어도 이미 분석한 리뷰는 저절로 다시 분석되지 않는다.

**키워드 판정 (Keyword judgment)**:
리뷰가 키워드를 표현했는지 정하는 일. 모델이 "말함"을 고를 확률이 0.9 이상이어야 하고, 구체적인 식감 키워드를 표현한 리뷰는 "식감이 좋아요"를 표현하지 않은 것으로 본다. 모델 질문의 선택지 "말함/안 말함"은 측정 조건을 지키려고 남긴 질문 문구이고, 도메인 용어가 아니다.

**키워드를 표현한 리뷰 (Review expressing a keyword)**:
키워드 판정을 통과한 리뷰. 표현이 달라도 뜻이 같으면 표현한 것이다("당도가 높아요"는 "달아요"를 표현했다). 아쉽다·나쁘다고 했거나, 평가 없이 사실만 적었거나, 걱정한 문제가 없었다는 안도만 있으면 표현하지 않은 것이다.
_Avoid_: 언급(분석 항목의 언급 없음과 겹친다), 사용, 포함, 말한(단어를 그대로 썼다는 뜻으로 읽힌다)

**키워드 집계 (Keyword summary)**:
한 상품의 키워드 분석 완료 리뷰 수와, 키워드마다 그 키워드를 표현한 리뷰 수. 현재 목록에 있고 상품의 현재 분류에 묻는 키워드만 센다. 분석 완료 리뷰가 10개 이상이고 리뷰 3개 이상이 표현한 키워드만, 많은 순으로 10개까지 구매자에게 보인다.

## 실험

**분류 기준 버전 (Criteria version)**:
`criteria.json`의 `version` 값. 질문 문구·선택지·안내문을 바꾸면 올린다. 모델 결과와 사람 정답에 함께 남겨 어느 기준으로 나온 값인지 구분한다.

**조정용 세트 (Tuning set)**:
명세를 다듬는 데 쓰는 리뷰 100개. 모델에 돌려 보고 헷갈린 사례로 명세를 고친다. 품질 점수에는 쓰지 않는다.

**평가용 세트 (Evaluation set)**:
사람 정답으로 품질을 재는 리뷰 300개. 정답을 다 매기기 전에는 어떤 모델에도 보내지 않고, 정답을 매기기 시작한 뒤에는 분류 기준을 바꾸지 않는다.
_Avoid_: 테스트 세트(단위 테스트와 헷갈린다)

**추가 비교용 세트 (Comparison set)**:
사람 정답 없이 두 모델의 일치율·속도·비용만 보는 리뷰 600개.

**사람 정답 (Gold label)**:
사람이 모델 결과를 보지 않고 매긴 정답. 모델이 만든 답은 정답으로 쓰지 않는다. 예외로 키워드 정답은 사람이 매길 시간이 없어 상위 모델이 매겼고(#387), 그 결과는 "모델 정답 기준"이라고 밝힌다.
_Avoid_: 라벨(모델 출력과 헷갈린다)

**생성 리뷰 (Synthetic review)**:
공공 데이터를 찾지 못해 모델로 만든 리뷰. `synthetic: true`로 표시하고, 결과는 "생성 데이터 기준"이라고 밝힌다.

**명세 점검 (Spec probe)**:
조정용 리뷰를 회사가 다른 고급 모델들에 돌려, 사람 답과 함께 다르게 고른 칸으로 명세가 애매한 곳을 찾는 일. 정답을 정하는 일이 아니다.
