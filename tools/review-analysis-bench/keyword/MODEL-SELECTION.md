# 키워드 자유 추출 모델 고르기 (#387 E1)

- **날짜**: 2026-11-05
- **상태**: 확정. `gpt-5.6-luna`를 쓴다 (사용자 결정, 2026-11-05). `extract.ts` 기본값
- **대상**: `keyword/extract.ts`. 목록용 리뷰에서 긍정 표현을 뽑아 키워드 목록 초안을 만들고, 측정용 리뷰에서 다시 뽑아 목록이 덮는 비율을 잰다. **서비스 모델(Jev)을 고르는 일이 아니다.** 서비스는 #385대로 Jev가 목록으로 판정한다.

## 왜 골랐나

처음에는 #385와 같은 `gpt-5.4-mini`로 시작했다. 사용자가 다른 추천 모델이 있는지 물었다. 상위 모델(`gpt-5.5`)을 추천하자 더 싼 모델을 찾자고 했다. 팀 프로젝트라 아주 높은 정확도가 필요하지 않고, **5.5를 100으로 볼 때 70~80 정도면 충분하다**는 이유였다(사용자 결정).

## 조건

| 조건 | 이유 |
|---|---|
| OpenAI 계열만 | 합성 리뷰를 Claude로 만들었다. 같은 계열 모델이 자기 문체를 잘 읽으면 덮는 비율이 부풀려진다 |
| 목록용과 측정용은 같은 모델 | 두 결과를 비교해 덮는 비율을 잰다. 모델마다 결과 파일을 나눈다(`extract-<pool>-<model>.jsonl`) |
| 날짜 붙은 스냅숏이 있으면 우선 | 나중에 같은 조건으로 다시 돌릴 수 있다 |

## 후보

API 키로 `GET /v1/models`를 불러 쓸 수 있는 모델을 확인했다. 가격은 2026-11-05 공식 가격표(standard, 100만 토큰당)다.

| 키 | 모델 | 입력 | 출력 | 추론 설정 | 스냅숏 |
|---|---|---|---|---|---|
| `5.5` | `gpt-5.5-2026-04-23` | $5.00 | $30.00 | low | O |
| `5.4` | `gpt-5.4-2026-03-05` | $2.50 | $15.00 | none | O |
| `terra` | `gpt-5.6-terra` | $2.00 | $12.00 | low | X |
| `luna` | `gpt-5.6-luna` | $0.20 | $1.20 | low | X |
| `mini` | `gpt-5.4-mini-2026-03-17` | $0.75 | $4.50 | none | O |

`gpt-5.6-sol`은 terra보다 비싸서 뺐다. 5.6 세 모델은 가격표에 설명이 없다.

## 방법

1. 먼저 `mini`와 `5.5`를 목록용 앞 10개에 돌려 결과를 나란히 봤다. 5.5가 낫다고 보고 5.5를 추천했다.
2. 더 싼 모델을 찾으려고 목록용 앞 30개(`pools.json`의 `list` 앞 30개)를 다섯 모델에 모두 돌렸다. 5.5와 mini는 앞 10개를 이미 돌린 상태라 실제로는 40개가 돌았고, 비교에는 앞 30개만 썼다.
3. **사람 정답이 없어 5.5 결과를 기준으로** 비교했다. 재는 값은 아래와 같다.
   - **5.5와 같은 리뷰 수**: 리뷰마다 뽑은 표현의 분석 항목 집합이 5.5와 같은지. 문구는 모델마다 조금씩 달라("입맛에 맞아요"와 "입맛에 잘 맞아요") 문구 대신 항목으로 비교했다.
   - **불만 리뷰에서 칭찬을 뽑은 수**: 5.5가 아무것도 뽑지 않은 리뷰 19개 중 그 모델이 무언가 뽑은 리뷰 수. 목록 초안을 더럽히는 오탐이다.
   - **근거 없음**: 모델이 준 근거 구절이 리뷰 본문에 없는 표현 수.
4. 결과가 다른 리뷰는 본문과 함께 직접 읽었다.

앞 30개 중 앞쪽은 #385의 어려운 사례 묶음(`hard-tuning`)이라 반어·부정 섞인 리뷰가 많다.

## 판단

- **luna로 정했다 (사용자 결정).** 다르게 뽑은 리뷰 3개가 모두 목록에 들어가지 않을 표현이거나 항목 차이뿐이었다. 오탐이 없고, 가격은 5.5의 약 1/25이다. 사용자가 정한 "5.5의 70~80" 기준을 넘는다고 본다. 30개 중 27개(90%)가 같다.
- **mini는 쓰지 않는다.** luna보다 비싸고 오탐이 있다.
- **대안은 `gpt-5.4`.** 스냅숏이 있어 나중에 같은 모델로 다시 돌릴 수 있다. 698개에 약 $1.0이다.

## 한계

- 리뷰 30개, 정답자는 사람이 아니라 5.5다. "5.5와 같음"은 "정확함"이 아니다. 5.5가 틀린 곳은 이 비교로 알 수 없다.
- 추론 설정이 모델마다 다르다(5.4·mini는 none, 나머지는 low). 각 모델에서 가장 싼 설정을 쓴 것이 아니라, #385에서 쓴 설정(none)과 none을 받는지 확인하지 않은 5.x 모델의 low가 섞였다.
- luna는 스냅숏이 없다. 같은 이름이 나중에 다른 모델을 가리킬 수 있으므로 **목록용과 측정용을 같은 시기에 이어서 돌린다.** 실행 날짜를 결과와 함께 남긴다.
- 30개 비용으로 698개를 추정했다. 리뷰 길이에 따라 달라진다.

## 다시 돌리기

```bash
cd tools/review-analysis-bench
for m in 5.5 mini 5.4 terra luna; do
  node --no-warnings --env-file=../../.env keyword/extract.ts --pool list --model $m --limit 30 --concurrency 6
done
```

비교 당시 결과는 `data/keyword/model-selection/`로 옮겼다. 비교 뒤 추출 지시문에 "안도 표현은 뽑지 않는다"를 더했으므로, 지금 명령으로 돌리면 비교 때와 지시문이 다르다. 이미 성공한 리뷰는 다시 보내지 않으므로, 처음부터 다시 비교하려면 `data/keyword/extract-list-<model>.jsonl`을 지우고 돌린다. `.env`는 29번째 줄의 `&` 때문에 셸 `source`로 읽히지 않아 `--env-file`을 쓴다.
