# keyword: 구매자 화면 리뷰 키워드 목록 만들기 (#387)

서비스는 미리 정한 긍정 키워드 목록으로 리뷰마다 "말함/안 함"을 Jev에 묻는다. 이 폴더는 그 목록을 만들고 검증하는 일회성 실험 도구다. 리뷰에서 자유 추출한 표현을 사람이 묶어 목록을 만들고, 목록을 만드는 데 쓰지 않은 리뷰로 목록이 표현을 얼마나 덮는지 잰다.

## 구성

| 파일 | 내용 | 커밋 |
|---|---|---|
| `keywords.json` | **키워드 목록과 판정 기준 문장.** 서비스로 옮길 파일 | O |
| `categorize.ts` | 생성 리뷰의 상품을 서비스 하위 분류 8개로 나눔 | O |
| `extract.ts` | 리뷰에서 긍정 표현 자유 추출 (gpt-5.6-luna) | O |
| `sheet.ts` | 추출 문구를 키워드로 묶은 검토 시트, 빠진 문구·범위 밖 매핑 검사 | O |
| `coverage.ts` | 측정용 리뷰로 목록이 덮는 비율 | O |
| `jev-spike.ts` | 키워드 질문을 담은 Jev 요청이 동작하는지 확인 (정밀도 측정 아님) | O |
| `gold-sheet.ts` | 키워드 정답 시트(조정용·평가용) 만들기·검사 | O |
| `precision.ts` | 정답 시트에 Jev를 돌려 정밀도·재현율, 확률 기준별 비교 | O |
| `list.ts` | 목록 읽기와 적용 분류 판단 (스크립트 공용) | O |
| `MODEL-SELECTION.md` | 추출 모델 고른 과정과 결과 | O |
| `data/keyword/` | 분류표, 리뷰 나누기, 추출 결과, 묶음 매핑, 네이버 칩, 측정 판정 | X |

## 진행 기록 (2026-11-05)

1. **상품 분류.** 생성 리뷰 1,000개의 상품 558개를 이름 규칙으로 8개 분류에 나눔. 애매한 상품(토마토는 과일, 찰옥수수는 곡물, 벌꿀은 가공품)은 사용자가 검토해 유지.
2. **리뷰 나누기.** 목록용 399개(조정용 100 + 추가 비교용 절반), 측정용 299개(추가 비교용 나머지 절반). 평가용 R0151 이후는 키워드 정답용이라 어디에도 넣지 않음. `data/keyword/pools.json`에 고정.
3. **자유 추출.** 목록용·측정용 698개를 gpt-5.6-luna로 같은 시각에 추출. 실패 0, 비용 $0.11. "다행히 안 터졌어요" 같은 안도 표현은 뽑지 않게 함(사용자 결정).
4. **목록 v0.1.** 목록용 표현 369개를 Claude가 묶어 34개 키워드 초안을 만들고 사용자가 검토. 리뷰가 적은 5개 분류는 공통 키워드만 씀(사용자 결정).
5. **네이버 칩 대조.** 사용자가 네이버 쇼핑 29개 상품의 AI 리뷰요약 칩(580개)을 모음. v0.1이 대상 칩의 86%를 덮음. 빠진 "크기가 적당해요"(15개 상품) 등을 더해 **v0.2**를 만듦. 배송·판매자 키워드는 상품 특징이 아니라 뺌(사용자 결정). 상품당 키워드 상한을 30개로 올림(사용자 결정. 화면에는 상위 10개만 보여 줌).
6. **판정 기준 문장.** 키워드마다 guide를 씀. 리뷰 5개로 Jev를 다시 돌리니 "크기가 적당해요", "탱글탱글해요" 오탐이 사라지고 "양념이 맛있어요"를 잡음. "쫄깃해요"에 "식감이 좋아요"도 함께 고르는 오탐은 남음. 요청당 입력이 약 5,400토큰에서 약 9,600토큰으로 늘어남.
7. **측정.** 측정용 299개에서 목록 v0.2가 대상 표현의 **92%(297/324)**를 덮음. 이슈 기준 70%를 넘음.
8. **목록 v0.3.** 측정용에서 빠진 포슬포슬해요·씨가 적어요·잘 익었어요·구성이 다양해요를 더함(사용자 결정). 그대로면 과일이 33개로 상한을 넘어, 키워드마다 "공통 또는 분류 하나" 대신 적용 분류 목록(`categories`)을 둠(사용자 결정). 적용 분류는 목록용 추출·측정용 판정·네이버 칩에서 그 분류에 나온 근거로 정함. 상품당 키워드는 나물 12개 ~ 가공품 30개. v0.3의 측정용 덮는 비율은 97%지만 측정용을 보고 고친 값이라 독립 측정이 아니다.
9. **키워드 정답 시트.** 평가용 R0151 이후에서 #385 감성 정답을 매긴 15개를 빼고 100개를 시드(20261106)로 뽑음. 가공품 33, 과일 33, 채소 12, 나물 7, 감자·고구마 5, 견과 4, 버섯 4, 곡물 2. 리뷰마다 "말한 키워드 id만 적기" 형식(`data/keyword/gold-keywords.csv`, 안내 `gold-keywords-guide.md`).
10. **정답자.** 사람이 매길 시간이 없어 상위 모델 gpt-6-astra high가 정답을 매겼다(사용자 결정). #385는 모델을 정답자로 쓰지 않았는데, 이번에는 시간 때문에 다르게 갔다. astra는 OpenAI 계열이라 합성 리뷰를 만든 Claude, 서비스 모델 Jev와 계열이 다르다. 그래서 아래 정밀도는 "사람 기준"이 아니라 "astra 판정과 같은 비율"이다.
11. **E3 조정용.** 정답 100개에 Jev(v0.3, 판정 기준 포함)를 돌림. Jev가 고른 답 그대로는 정밀도 0.675, 재현율 0.940. 오탐은 "맛있어요"(구체적인 맛 칭찬에 같이 고름)와 "식감이 좋아요"(구체적인 식감 키워드와 같이 고름)에 몰림. "말함" 확률 0.9 이상만 쓰고, 구체적인 식감 키워드가 있으면 "식감이 좋아요"를 빼는 규칙(판정 기준을 코드로 옮긴 것)을 넣으면 정밀도 0.926, 재현율 0.750. 같은 설정으로 두 번 돌렸을 때 "말함"이 113개, 117개로 달라 Jev 답이 실행마다 조금 흔들린다. **이 100개로 기준을 골랐으므로 0.926은 조정용 점수다.**
12. **E3 평가용 시트.** 설정(확률 0.9 이상 + 식감 규칙)을 고정하고, 남은 평가용 134개에서 조정용과 겹치지 않게 100개를 시드(20261107)로 뽑음(`data/keyword/gold-keywords-eval.csv`). 정답을 매긴 뒤 한 번만 잰다.
13. **E3 평가용 결과.** gpt-6-astra high가 평가용 100개에 정답을 매김(말한 키워드 95개, 말한 키워드 없는 리뷰 48개). 고정 설정에서 **정밀도 0.942(65/69), 재현율 0.684(65/95)**. 이슈 기준 0.9를 넘음. 조정용(0.926)과 비슷해 설정이 조정용에만 맞춘 결과는 아니라고 본다. Jev 기본값 그대로는 0.690이었다.

## E3 결과 (목록 v0.3, 평가용 100개)

| 설정 | 정밀도 | 재현율 |
|---|---|---|
| Jev가 고른 답 그대로 | 0.690 (87/126) | 0.916 |
| **확률 0.9 이상 + 식감 규칙 (고정 설정)** | **0.942 (65/69)** | **0.684** |

- 정답은 사람이 아니라 gpt-6-astra high 판정이다. 정밀도는 "astra 판정과 같은 비율"이다.
- 판정한 칸이 69개뿐이라 95% 신뢰구간이 약 0.86~0.98(Wilson)이다. **0.9 아래일 가능성을 배제하지 못한다.** 실제 리뷰가 쌓이면 다시 잰다.
- 재현율은 정답 키워드의 약 3분의 1을 놓친다는 뜻이다. 가장 많이 놓친 키워드는 "크기가 고르고 깨끗해요"(3회)다. 칩은 상품 하나에서 리뷰 3개 이상이 말해야 나오므로, 놓치는 만큼 칩이 늦게 나타난다.
- 평가용 결과를 본 뒤에는 설정을 바꾸지 않았다. 표의 다른 확률 기준 값은 `precision.ts`가 함께 출력하지만, 고르는 데 쓰지 않았다.
- 서비스로 옮길 것: `keywords.json`, Jev 답의 "말함" 확률 0.9 이상만 세기, 구체적인 식감 키워드(C18·C19·C20·C21·C22·C23·C26·C28)가 있으면 "식감이 좋아요"(C25)를 빼는 규칙.

## 한계

- **새 문구 판정을 Claude가 했다(사용자 요청).** 잡힌 297개 중 173개가 측정용에서 처음 나온 문구라 판정이 필요했고, 목록을 묶은 쪽이 판정했다. 판정은 `data/keyword/measure-judgments-v0.2.json`에 모두 있다. 목록 매핑에 이미 있던 문구만 세면 124/324(38%)로, 이 값이 판정을 모두 틀렸다고 볼 때의 하한이다.
- 생성 리뷰는 Claude가 만들었고 실제 구매자 표현이 아니다. 실제 리뷰가 쌓이면 같은 방식으로 다시 잰다.
- 측정용 결과를 본 뒤 목록을 고치면 측정이 아니게 된다. 위 후보를 넣으려면 v0.3으로 올리고, 92%는 v0.2의 값으로 남긴다.
- 덮는 비율은 "목록에 그 뜻의 키워드가 있는가"다. Jev가 그 키워드를 맞게 고르는지(정밀도 0.9)는 키워드 정답 100개로 따로 잰다.
